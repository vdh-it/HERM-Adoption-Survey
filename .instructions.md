# Project Instructions: HERM Usage & EA Adoption Research

## Project Context

This is a research project studying how Enterprise Architecture (specifically HERM as a core artifact collection) is being adopted in Higher Education institutions. The work aims to:

1. **Understand adoption drivers:** What motivates HE institutions to adopt HERM?
2. **Identify use cases:** For what specific purposes is HERM being used?
3. **Capture patterns:** What implementation patterns emerge across institutions?
4. **Share knowledge:** Create resources that help other institutions learn from experiences

## Key Concepts

### HERM (Higher Education Reference Model)
- An enterprise architecture reference model designed specifically for higher education
- Provides comprehensive artifact collections for EA documentation
- Used by institutions for strategic planning, IT governance, and organizational alignment

### Case Study Focus
We collect and analyze **real adoption stories** from HE institutions, focusing on:
- **Motivations:** Why did they adopt HERM/EA?
- **Implementation:** How did they approach it?
- **Outcomes:** What did they achieve?
- **Challenges:** What obstacles did they face?
- **Lessons learned:** What would they do differently?

## Working with AI Agents

### How to Work Most Effectively

When researching or analyzing case studies:

1. **Provide context:** Always include the institution type, HERM adoption phase, and key questions
2. **Use specialized agents:** The project has agents for:
   - **Case Study Synthesizer:** Analyzing multiple case studies for patterns
   - **Theme Extractor:** Identifying common themes across institutions
   - **Gap Analyzer:** Finding missing information or contradictions
   
3. **Iterate:** Analysis is progressive—each round of insights informs the next

### Research Workflows

#### Collecting a New Case Study
1. Use the case study template (`docs/templates/case-study-template.md`)
2. Conduct interviews or gather documentation
3. Submit to agent for initial analysis & pattern matching

#### Analyzing Patterns Across Cases
1. Specify the research question (e.g., "What are common implementation barriers?")
2. Use Case Study Synthesizer agent
3. Get structured findings with evidence references

#### Building Frameworks
1. Identify recurring themes from analysis
2. Use Framework Builder agent to structure findings
3. Create reusable templates for future analysis

## Important Guidelines

### Research Quality
- **Source documentation:** Every insight should trace back to case study data
- **Neutrality:** Present motivations objectively—avoid bias toward success stories
- **Context matters:** Always note institutional size, sector, prior EA experience

### Case Study Confidentiality
- Anonymize sensitive information unless institution has approved disclosure
- Focus on learning, not criticism
- Always offer findings back to participating institutions

### Analysis Standards
- Use multiple case studies to validate patterns (minimum 3 before claiming a pattern)
- Note degree of evidence (all cases, most cases, some cases)
- Acknowledge alternative explanations

## File Organization

**Case Studies:** `data/case-studies/` - One file per institution
**Metadata:** `data/metadata.json` - Searchable index of all cases
**Analysis:** `analysis/patterns/` - Themed analysis outputs
**Reports:** `analysis/reports/` - Synthesis documents & findings
